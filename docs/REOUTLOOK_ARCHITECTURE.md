# ReOutlook 架构与同步

ReOutlook 在一个 Android 应用中组合 Outlook 官方网页和本地离线邮件档案。在线身份认证、MFA 和邮件操作仍由 Outlook Web 完成；原生层只保存明确捕获到的结构化邮件数据，不接收网页认证秘密。

## 在线与离线界面

- 在线界面使用系统 WebView 打开 `https://outlook.office.com/mail/`，保留官方网页和学校认证流程。
- 应用控制收纳在可拖拽、半透明、自动吸附并记忆位置的悬浮球抽屉中。
- 本地邮件列表按收件时间显示缓存内容，正文只在打开详情时从 SQLite 读取。
- 离线正文 WebView 禁用 JavaScript、网络请求、本地文件访问和页面跳转。
- 系统返回先处理临时界面和网页历史，再回到邮箱主页，最后使用两秒内二次返回退出。

## 结构化邮件采集

应用在 Outlook 页面启动前安装受来源限制的 AndroidX WebKit 消息桥，观察 Outlook Web 已经取得的结构化服务响应：

1. `FindConversation` 提供会话目录、修订标识和分页信息；
2. `GetConversationItems` 提供会话内邮件和正文；
3. 正文缺失时按 Outlook 当前协议补充执行单项 `GetItem / ItemPart`；
4. 实验性 DOM 适配器仅作为当前打开邮件的回退路径。

认证头和请求上下文只在 Outlook 页面 JavaScript 内存中临时复用，不通过原生桥传递，也不写入数据库。

## 历史回填与完成条件

回填从新到旧限速运行，每次应用启动最多新增处理 50 个会话。长会话将 `MaxItemsToReturn` 从 20 逐步提升到 30、40，直至最多 100。

一个会话只有在以下条件全部满足后才提交检查点：

- HTTP 请求成功；
- Outlook 服务状态成功；
- 返回节点数量和正文完整性通过检查；
- 草稿已经排除；
- 原生 SQLite 确认写入预期数量的邮件。

同一轮邮件写入和 `conversationComplete` 使用相同 `syncToken`，并通过 `expectedMailCount` 防止网页侧在原生写入不完整时误报完成。

检查点保存 Outlook 的远端修订标识。会话没有变化时跳过；新增回复或 `ChangeKey` 变化后重新同步。远端删除和移动语义仍在继续验证。

## 账号隔离

数据库当前为 schema v4：

- 优先使用稳定 PUID 建立账号键；
- SMTP 地址和 PUID 别名可合并为同一账号；
- 邮件、唯一索引和同步检查点全部绑定账号键；
- 升级时保留旧缓存并重建账号范围内的唯一约束。

真实设备上的 v2 → v4 无损迁移曾以 612 封历史邮件和 579 个检查点验证通过。第二个真实 Outlook 账号的端到端隔离仍待验证。

## 本地存储

邮件数据库位于 Android 凭据加密的应用私有目录，依赖应用沙箱和 Android FBE。当前没有使用 SQLCipher，因此设备解锁后若数据库被单独提取，内容没有额外的整库密钥保护。

Android 自动备份已关闭。普通用户备份与恢复尚未完成；后续流程必须显式授权，并在恢复时验证目标账号。

## 管理员维护

ReOutlook 的维护组件没有桌面或普通应用入口，并受 `android.permission.DUMP` 限制。邮件导出必须同时满足：

1. 对绑定安装 ID、账号、操作、随机 nonce 和有效期的一次性挑战提交 RSA-3072/SHA-256 管理员签名；
2. 机主在前台通过 Android 系统锁屏凭据确认。

导出内容使用随机 AES-256-GCM 密钥加密，该密钥再由独立 RSA-3072 导出公钥通过 RSA-OAEP 包装。导出不包含密码、Cookie、Token 或 Web Storage。使用方法见 [`tools/admin/README.md`](../tools/admin/README.md)。
